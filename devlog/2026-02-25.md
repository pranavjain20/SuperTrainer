## What got built

### Set-level observation attachment

The core feature: observation cards can now target a specific exercise and set. Before today, if a trainer said "left is tougher than right on the clamshells," that became a floating note with no connection to the exercise. The DB already had `attached_to_set` — it was designed for exactly this — but nothing populated it.

Two new optional fields on the observation card tool schema (`target_entry_id` and `attached_to_set`), threaded through the full pipeline. `target_entry_id` is transient — it tells validation which exercise the observation is about, but only `attached_to_set` gets stored in the DB. The exercise relationship is implicit via timeline ordering.

### The judgment call that matters

The hardest part wasn't the plumbing — it was teaching Claude *when* to attach and when not to. There's a real distinction between:

- **During-exercise speech**: "lower back pain after rep 7 on set 3" — embedded in set data, exercise named. Attach it.
- **Between-exercise speech**: "his lower back is hurting" — standalone comment between exercises, no set data. Don't attach it.

The first version of the prompt got this wrong. Claude saw "lower back pain" + deadlifts in context and inferred the connection. Reasonable logic, wrong behavior. When I described the actual training session flow — how the trainer checks in *between* exercises, how "Pranav's lower back is hurting" is about the client's state at that moment, not about deadlifts specifically — the distinction became clear. If the trainer meant to connect it, they'd say "from those deadlifts." The absence of an explicit reference is the signal.

Three prompt rules (19, 22, 23) now control this. Tested against 5 live Claude scenarios — all passing.

### Temporal context for session-level observations

This came from a product realization mid-session. "Energy levels are lower" as a standalone observation is almost useless — you already know from the first observation that I hadn't slept enough. What makes it valuable is *when* it was said. After clamshells and squats, energy dropped further. The progression is the insight.

The fix was one prompt rule (Rule 23): when creating session-level observations, reference what exercises have been completed. Claude now writes "energy levels dropping further after clamshells and squats" instead of just "energy levels dropping." It already had the context — we just told it to use it.

### Live Claude testing

Five scenarios, all verified against real Claude API:

1. **Set-specific pain** ("third set deadlifts 12 reps slight lower back pain after seventh rep") → observation attached to entry [1], set 3. **PASS.**
2. **General complaint** ("Pranav is complaining about his lower back") → session-level, no attachment, text includes "after completing deadlifts." **PASS** (after prompt fix).
3. **Exercise-level observation** ("left glute was a bit painful on the clamshells") → attached to entry [1], no specific set. **PASS.**
4. **No context** ("left glute was a bit painful") → both fields empty. **PASS.**
5. **Mid-session energy** ("energy levels are even lower now") → session-level with temporal context: "after clamshells and squats." **PASS.**

## The market insight, confirmed

I've been building toward this realization for a while, but today's session crystallized it. Trainers don't know how good tracking *could* be because they've never had a world where capturing everything was possible. Writing is slow, memory is limited, so they self-censor. They stop even thinking about all the information exchanged during a session because they've internalized that it can't be captured.

This isn't a market where trainers have a burning problem and are looking for a solution. The baseline is so low that trainers don't even have awareness of how much better they could be. There's no sense that "so much more can be done" — because nothing like this exists. The unlock is convenience: if speaking into a phone for 5 seconds captures what would take 2 minutes to write, trainers will actually do it. And once they start capturing more, and the Brain starts surfacing insights from that data, that's when the real hook lands.
