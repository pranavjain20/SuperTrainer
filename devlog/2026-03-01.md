# Day 1 — Design System Polish (Mar 1, 2026)

Phase 2a ended and I thought I was ready to add more features. The plan was always: build backend, build mobile app, show it to a trainer, get feedback. By the end of Phase 2a I had something workable.

Then I actually thought about what "show it to a trainer" means. It's not a demo. If a trainer likes it, they might want to keep using it. I can't hand someone a functional app that looks like a developer built it for themselves. It has to look like something I'd download from the App Store. Not because aesthetics matter more than features — but because first impressions are permanent. If the first thing they think is "this looks unfinished," nothing else matters.

So how did I actually do it? My first assumption was that Claude is great at backend and AI code, but probably not at frontend design. It can write React Native, sure — but making something look *beautiful* is a different skill. So I started thinking about how to maximize what Claude can do instead of just accepting the limitation.

I talked to Claude and realized I could give it a markdown design spec — a document describing exactly how the app should look — and it would follow it precisely when writing components. That changed everything. Instead of hoping for good defaults, I could define the system upfront.

So I had Claude do deep research: what are the best fitness apps out there? What makes each one's UI work? I had it analyze the design patterns across multiple top apps, pull out the best practices from each, compress them down, and combine everything into a single design system document — the token system, the typography scale, the color palette, the spacing rules. A complete visual language spec that I could hand to Claude Code and say "follow this for every component."

The result: 40+ components migrated to the new system. Home screen session cards went from bloated 3-line layouts to tight 2-line cards where the client name is the first thing you read. Section headings that were invisible tiny uppercase text became proper headers. I look at the app now and it looks like a real product. That feeling — "this looks like something a professional made" — is exactly what I needed before putting it in anyone else's hands.

The other thing I noticed today: Claude's debugging pattern. Something broke during the design migration and Claude spent an hour going in circles trying different fixes. It would try something, it wouldn't work, try something else, still broken. No systematic approach. I finally stepped in and said "stop — let's backtrace from the symptom." We traced it back and the root cause was simple. This is exactly what happens to me at work — I'll spin on something for two hours, then a senior engineer asks three questions and we find it in a minute. The difference is they don't panic. They trace backward instead of flailing forward. I need Claude to do that, and honestly, I need to do that better myself too.
