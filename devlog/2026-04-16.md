# Apr 16, 2026 — Plan Creation (Natural Language → Structured Exercises)

## What Got Built

Plan creation with natural language input → AI parsing → structured editable exercises. Full CRUD: create, edit, delete from the client profile Plans tab. Voice input supported (Deepgram transcription → Claude parsing → exercises appear in edit mode).

**Backend:**
- `planned_exercises` JSONB column on `session_plans` (migration)
- `POST /api/v1/plans/parse` — Claude tool_use endpoint that parses natural language into structured exercises (exercise_name, sets, reps, weight as separate fields)
- `POST /api/v1/transcribe` already existed — reused for voice input
- Plan parser service (`plan_parser.py`) with gym-specific prompt

**Mobile:**
- Plan form screen (`app/plans/form.tsx`) with two modes: input (text + voice) → edit (structured fields)
- `createPlan()` API function (was missing)
- `usePlans.ts` hooks — create, update, delete, parse mutations
- PlanCard updated to display structured exercises in compact session format
- Plans tab has "+ New Plan" button, cards are tappable for editing

## Design Decisions

**Natural language input, not form builders.** Every competitor app (TrueCoach, Trainerize, Everfit, etc.) uses structured form builders: pick exercise → enter sets/reps/weight → repeat. The #1 complaint across all of them: too many clicks. We replace the input method with natural language (type or speak) and keep the output format trainers already know. No app in the market does voice-first plan creation on the coach side. See `devlog/2026-04-16-plan-research.md` for full competitive research.

**Structured fields for editing, not one text string.** Went through multiple iterations: single prescription string ("4x10 @ 10kg"), combined name+prescription, split name+prescription. Landed on separate sets/reps/weight fields because the trainer needs to edit individual values (change reps from 10 to 8) without rewriting the whole string. Each field is independently tappable.

**Edit the output, not the input.** After AI parses, the trainer edits the structured exercises directly. No re-parse round-trip. If the AI gets 90% right, fix the 10% inline.

**Voice auto-parses.** Speaking skips the text area entirely — goes straight to transcription → parse → edit mode with exercises listed. The parsed exercises ARE the verification (easier to verify "Squats / 4 / 10 / 10kg" than raw transcript text).

**Plan display matches session compact format.** PlanCards use the same visual structure as ExpandableSessionCards: date as heading, workout type as uppercase blue label, exercises with compact set notation (10kg×10, 10kg×10). One visual language across past sessions and future plans.

**Parser always names the workout.** "Legs" → "Leg Workout". The parser infers workout type from exercises (all lower body → "Leg Workout", mix → "Full Body Workout") and always provides a name.

**Uniform values shown once, varying values listed.** If all 4 sets are 10kg, show "10kg" once. Only list "10kg, 12kg, 15kg" when weight varies per set. Same rule for reps.

## Known Issues / Next Session

1. **Plan not shown during session** — creating a plan works, but when you start a session, the plan is invisible on the recording screen. Need to wire plans into the session flow (show today's plan, auto-link via `plan_id` FK).
2. **"Done" button on ended session** — shows status but isn't actionable. Should navigate back.
3. **Add exercise button** — may have tap issues on some interactions.
4. **Edit affordance on plan cards** — pencil icon helps but could be clearer.
