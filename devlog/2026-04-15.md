# Apr 15, 2026 — Live Exercise History

## What Got Built

Recording screen now has [This Session] | [History] segmented control. History tab shows the client's past sessions as expandable cards. This is the #1 daily trainer action — checking what weight/reps a client did last time before starting an exercise.

## Design Decisions

**Notebook page flip model.** The trainer's current workflow: notebook is open, flip back to see previous sessions, flip forward to current page. Digital equivalent: segmented control on the recording screen. One tap to flip, no modals, no leaving the page. Record button visible on both tabs.

**Organized by date, not by exercise.** Trainers think in sessions ("last leg day"), not exercises. Session list is 3-5 items to scan; exercise list could be 30+. Date is sorted descending so position alone tells recency.

**Collapsed card hierarchy.** Date is secondary context (already sorted). Workout type is a small uppercase label ("FULL BODY"). Exercise names are the primary scannable content — that's what the trainer is looking for. Tap to expand for actual numbers.

**Expanded card shows everything.** Exercise name bold on its own line, all sets below in monospace. No truncation — if the trainer expanded to see numbers, show all the numbers. Blue left accent border distinguishes expanded from collapsed.

**summaryOnly mode.** History cards only toggle collapsed/summary. No detail view with full set tables — that's for the client profile, not mid-session lookup.

**No backend changes.** Reuses existing useClientSessions + useClientEntries hooks. React Query caches the data.

## UI Principles (confirmed through iteration)

- Buttons/controls must be big, bold, obviously tappable
- Labels should be small — don't let categories overpower the content
- Don't truncate data the user explicitly opened to see
- Tight spacing — excess whitespace looks unpolished and wastes screen real estate
- Remove info that doesn't serve the current context (e.g., session time during recording)

## Bug Fix: End Session UI Not Updating

Ending a session via the recording screen succeeded on the backend but the UI stayed on "In Progress." Root cause: `useEndSession` only called `invalidateQueries` on success, which marks the cache stale and waits for a background refetch. That refetch isn't guaranteed to fire immediately with tab switching and competing queries.

Fix: added `queryClient.setQueryData(["sessions", sessionId], updatedSession)` to write the mutation response directly into the React Query cache. UI transitions instantly.
